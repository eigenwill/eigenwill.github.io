从文章到发布，三步就好

日常发布
  1. 01

    写好文章

    使用 .md 文件，可从模板开始。标题、日期、分类和标签放在文件开头的 YAML 信息区。

  2. 02

    上传并提交

    点击「上传 Markdown」，在 GitHub 登录后拖入文件。点击 Commit changes，将改动提交到 master 分支。

  3. 03

    等待自动发布

    GitHub Actions 会构建博客。打开「发布状态」，最近一次流程显示绿色后，刷新博客查看文章。通常需要几分钟。

发布前，检查一下

仅在本地读取

检查文件名与常用文章信息，不上传文件。

拖入一个 Markdown 文件

支持 .md / .markdown，最大 2 MB

此处只做基础检查。发布仍需在 GitHub 提交文件，最终结果以构建状态为准。

文章格式

下载模板 ↓
---
title: "我的新文章"
date: "2026-10-18"
description: "一两句话，介绍这篇文章。"
category: "学习笔记"
tags: ["笔记", "随想"]
slug: "my-new-post"
draft: false
---

## 从这里开始

写下你的正文。

draft: true 会保留文章，暂不发布。CMS 新文章默认为草稿，发布时请关闭「草稿」。
没有 YAML 信息区的 Markdown 也可以上传，系统会自动补全基本信息。

内容保存在你的 GitHub 仓库

无需另外租用服务器。此管理入口可以公开访问，编辑、上传与删除操作由 GitHub 登录和仓库权限保护。页面不会保存访问令牌。
